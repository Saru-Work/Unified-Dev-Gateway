OPENGATE (Unified Dev Gateway)
==============================

WHAT IS IT?
-----------
OpenGate is an API marketplace built on WSO2 API Manager. Developers sign up
once, browse a catalog of documented APIs, and call any of them with one set
of credentials, instead of signing up with every API provider.

WSO2 API Manager is the engine: it secures every call, enforces subscriptions
and rate limits, and runs the gateway. OpenGate is the front door:

  - Developers get their own OpenGate account (email + password).
  - They browse the catalog, with every endpoint documented and a
    ready-to-run example for each.
  - They create applications, subscribe them to APIs, generate keys and get
    access tokens, all self-service. OpenGate does the WSO2 work with its own
    service account, so developers never need a WSO2 login.
  - For APIs whose provider needs a key (e.g. NASA), OpenGate holds the key
    and the gateway adds it to each call. A shared limit keeps everyone
    within the provider's quota.
  - Each application shows its usage: calls, errors, throttling, latency.
  - OpenGate remembers who owns each application, so every developer sees
    only their own.

The pieces:

  dashboard  (port 3000)  The web portal, with a user guide at /docs.
  backend    (port 4000)  The OpenGate REST API (OpenAPI at /openapi.json).
  WSO2 APIM  (port 9443)  The API manager OpenGate drives;
             (port 8243)  its gateway, where applications call APIs.
  MongoDB                 Accounts, application ownership, usage events.

Everything runs together with:  docker compose up --build -d
Add 19 sample public APIs with: scripts/seed-public-apis.sh


WHAT CAN I DO WITH IT TODAY?
----------------------------
In the dashboard (http://localhost:3000), or through the REST API:

  - Sign up, sign in, change your password.
  - Browse and search the API catalog by category; read each API's endpoints,
    parameters and real example responses.
  - Create, edit and delete applications, with a throttling policy.
  - Subscribe an application to an API on a tier (Bronze, Silver, Gold,
    Unlimited) and unsubscribe.
  - Generate production and sandbox keys, get an access token in one click,
    delete keys if a secret is lost.
  - Call the API through the WSO2 gateway with that token.
  - See each application's usage over 24 hours, 7 or 30 days.

Built-in protections:
  - Passwords are stored as argon2 hashes, never in plain text.
  - Sign-up, login and password changes are rate-limited.
  - You can never see or confirm another user's applications.
  - Consumer secrets are shown once and never stored by OpenGate.
  - Provider keys are stored encrypted in WSO2, and masked in responses
    from providers that echo them back.
  - If WSO2 creates an app but OpenGate fails to save it, OpenGate deletes
    the app from WSO2 again so nothing is left without an owner.


WHAT IT CAN'T DO YET
--------------------
  - No "stay logged in": sessions last 15 minutes, then you sign in again.
  - Regenerating a consumer secret fails on WSO2 4.7.0; delete the keys and
    generate new ones instead.
  - All applications live under one WSO2 account, so application names must
    be unique across all users.
  - A provider key is shared by every developer; there is no fair share per
    application yet.
  - No plans or billing, no provider self-onboarding, no client SDK, and no
    automated end-to-end tests against a live WSO2 yet.
